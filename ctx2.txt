## Suggested Better Abstraction

### Option 1: Context Manager Based
Create a `TrackedGroup` context manager that automatically handles group lifecycle:

```python
class TrackedGroup:
    """Context manager that handles group lifecycle with the tracker."""
    def __init__(self, tracker, group_id):
        self.tracker = tracker
        self.group_id = group_id
    
    def __enter__(self):
        return self.group_id
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.tracker.remove_group(self.group_id)
        return False
```

Then usage becomes:
```python
with TrackedGroup(tracker, gid) as group_id:
    # Do work with group_id
    # Automatic cleanup on exit
```

This eliminates scattered cleanup calls and makes the lifecycle explicit.

### Option 2: Builder Wrapper / Decorator Pattern
Wrap the `EnvGroupBuilder` with tracking behavior:

```python
class TrackedEnvGroupBuilder:
    """Wraps an EnvGroupBuilder and automatically integrates with progress tracking."""
    def __init__(self, builder, tracker):
        self.builder = builder
        self.tracker = tracker
        self.group_id = tracker.allocate_group_id()
    
    def build(self):
        env = self.builder.build()
        self.tracker.update_group(self.group_id, env)
        return env
```

This approach keeps tracking logic encapsulated within the wrapper, so the builder itself stays clean and the tracker integration happens transparently during the build process.

### Option 3: Event-Based / Observer Pattern
Instead of direct method calls, use an event system where the trainer emits signals:

```python
class TrainingEvents:
    def __init__(self):
        self.listeners = []
    
    def group_started(self, group_id): ...
    def trajectory_sampled(self, group_id, traj_id): ...
    def group_completed(self, group_id): ...
```

Listeners subscribe to these events and react accordingly, decoupling the trainer from specific tracking implementations.

### Option 4: Protocol-based abstraction
Define protocols that specify the minimal interface needed:

```python
class TrackableGroup(Protocol):
    @property
    def tracking_id(self) -> int: ...

class GroupTrackingHandle:
    def update_trajectory(self, idx: int, tokens: int): ...
    def mark_sampled(self, idx: int): ...
    def complete(self, rewards: list[float]): ...
```

This approach uses RAII-style handles that automatically clean up when they go out of scope, removing the need for explicit cleanup calls.

### Recommended approach

Split the tracking logic into separate modules—one for core tracking operations and another for display/visualization. Use handle objects returned from `tracker.track_group()` that manage their own lifecycle through `__del__`, eliminating the need to attach state directly to builder objects. Instead of monkeypatching attributes onto instances, pass the handle explicitly through function calls or store it in a context manager.

An async context manager wrapping the entire group lifecycle would clean up the train.py code significantly—replacing the current pattern of manual allocation, try/except blocks, and scattered cleanup calls with a single `async with tracked_rollout(tracker, builder):` block that handles setup and teardown automatically.

```python
class GroupHandle:

        self.tracker.complete_group(self.group_id, rewards)

        self.tracker.mark_trajectory_training_enqueued(self.group_id, traj_idx)

        self.tracker.mark_trajectory_fwd_bwd_done(self.group_id, traj_idx)

        if not self._closed:
            self.tracker.remove_group(self.group_id)
            self._closed = True
    
    def __del__(self):
        self.close()
```

# Plan: Simplify Progress Tracking Abstraction

## Goal
Replace the complex `TrajectoryProgressTracker` (singleton, ID registry, context vars, monkeypatching) with a simpler design where progress state lives directly on `EnvGroupBuilder`.

## Current Problems
- Monkeypatching `_progress_group_id` onto builders
- ID allocation and registry lookups in singleton
- Context vars passing IDs through call stack
- Scattered lifecycle management
- 900-line file mixing tracking with display code

## New Design
Progress state lives on the object it describes:
```
EnvGroupBuilder.progress: GroupProgress | None
  └── trajectories: list[TrajectoryProgress]
        └── status, training_status, tokens, reward, timing...
```

Write-on-change: Each state update writes to JSON (like current `_write_state()`).

```python
@dataclass
class GroupProgress:
    group_id: int
    trajectories: list[TrajectoryProgress]
    start_time: float = field(default_factory=time.time)

    def to_dict(self) -> dict: ...

# Global registry of active groups (for write_progress)
_active_groups: dict[int, GroupProgress] = {}
_write_lock = threading.Lock()
_next_group_id: int = 0

def register_group(progress: GroupProgress) -> None:
    with _write_lock:
        _active_groups[progress.group_id] = progress
    _write_progress()

def unregister_group(group_id: int) -> None:
    with _write_lock:
        _active_groups.pop(group_id, None)
    _write_progress()

def allocate_group_id() -> int:
    global _next_group_id
    with _write_lock:
        gid = _next_group_id
        _next_group_id += 1
    return gid

def _write_progress() -> None:
    """Write current state to JSON file."""
    with _write_lock:
        state = {
            "timestamp": time.time(),
            "groups": {gid: g.to_dict() for gid, g in _active_groups.items()},
        }
    PROGRESS_FILE.write_text(json.dumps(state))

# Minimal context var for tinker_openai.py
_current_trajectory: ContextVar[TrajectoryProgress | None] = ContextVar("traj", default=None)

def set_current_trajectory(progress: TrajectoryProgress | None) -> None:
    _current_trajectory.set(progress)

def set_trajectory_context(prompt_tokens: int) -> None:
    """Update current trajectory's token count (called in tinker_openai.py)."""
    traj = _current_trajectory.get()
    if traj is not None:
        traj.tokens = prompt_tokens
        _write_progress()

def set_trajectory_sampled(total_tokens: int) -> None:
    """Mark current trajectory as sampled (called in train.py after rollout)."""
    traj = _current_trajectory.get()
    if traj is not None:
        traj.tokens = total_tokens
        traj.status = TrajectoryStatus.SAMPLED
        traj.end_time = time.time()
        _write_progress()
```
